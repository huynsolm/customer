# 카페 발주·입고·재고 관리 (v0.2 — 품목 5개, 매장 1곳)

```bash
python server.py            # http://localhost:8000 (cafe.db 자동 생성, 샘플 품목 5개)
python -m unittest -v       # 테스트 35개(업무 사례 시나리오 포함, Claude API는 호출하지 않음)
```

포트·DB 경로는 환경변수 `PORT`, `CAFE_DB`로 바꿀 수 있다. 같은 포트에 서버를 두 번 띄우면 두 번째는 바로 실패한다.

## 업무 사례 (scenarios.json → test_scenarios.py가 그대로 재생)
1. **정상 입고**: 원두가 기준(2kg) 이하 → 5kg 발주 → 5kg 도착 → 입고 완료
2. **부분 입고**: 우유 10개 주문 → 8개 도착(입고 버튼 더블클릭 포함) → 잔량 초과 입고 거부 → 거래처 결품으로 잔량 취소
3. **수량 정정**: 컵 80개 도착인데 100으로 입력 → 마감 전 장부 110 vs 실제 90 → 이력에서 원인 확인 → 입고 기록 100→80 정정 → 실사 차이 0

새 예외 사례는 scenarios.json에 단계만 추가하면 반복 검증된다.

기본 기능은 의존성 없음(Python 3.13 표준 라이브러리 + SQLite).

## 부족 품목 요약 (AI는 숫자를 만들지 않는다)
- **계산**(`inventory.shortage_report`): 최근 7일 사용·폐기량(정정 반영) → 하루 평균, 남은 일수, 입고 예정 수량, 권장 발주량 = 7일분 + 발주 기준 − (현재고 + 입고 예정). 재고 목록 화면에 바로 표시되고 "발주" 버튼으로 권장량을 발주한다.
- **문장화**(`summary.py`): 기본은 규칙 기반 문장. "AI로 다시 쓰기"를 누르면 계산 결과 JSON을 Claude(`claude-opus-5-5`)에 넘겨 3문장 이내로 다시 쓴다.
- **안전장치**: 답에 입력에 없는 숫자가 하나라도 있으면 버리고 규칙 기반 문장을 쓴다. 패키지·인증 정보가 없거나, API 오류·거절이 나도 같은 문장으로 대체하고 이유를 화면에 표시한다.
- Claude를 쓰려면 `pip install -r requirements.txt` 후 `ANTHROPIC_API_KEY`를 설정한다(또는 `ant auth login`).
- 가정한 업무(일주일분 발주 등)는 [virtual-interview.md](virtual-interview.md)에 있다.

## 설계 요점
- **재고 = 변동 이력(stock_movements)의 합계.** 수량 컬럼을 직접 고치지 않으므로 이력과 재고가 어긋날 수 없다.
- **중복 방지**: 모든 쓰기 요청에 `idempotency_key`(UNIQUE). 입고 버튼을 두 번 눌러도 첫 결과를 돌려준다.
- **동시성**: 쓰기는 `BEGIN IMMEDIATE`로 직렬화. 스레드 8개가 동시에 사용량을 기록해도 합계가 맞다(테스트).
- **정정**: 삭제 없이 차이만큼의 `correction` 기록을 추가(0 = 취소). 사유 필수.
- **부분 입고**: 발주 상태(발주됨/부분 입고/입고 완료/종결)는 입고 합계에서 계산. 잔량 초과 입고 거부, 잔량 취소 가능.
- **마감**: 실사 수량과 장부 차이를 `adjustment` 기록으로 남긴다.

## 검증 구분 (포트폴리오용)
| 구분 | 내용 |
|---|---|
| 실제 검증 | 자동 테스트(부분 입고, 발주·입고 중복 클릭, 초과 입고, 정정, 음수 재고 방지, 동시 기록, 업무 사례 3개), 브라우저에서 발주 더블클릭 → 입고 8 더블클릭 → 초과 입고 오류 → 이력에서 정정 흐름 확인 |
| 코드 검수에서 발견·수정 | 같은 요청 키를 다른 작업에 쓰면 기록이 조용히 누락 / 마감 실사 이전 기록을 정정하면 차이가 두 번 반영 / 빈 요청 키끼리 충돌 / 음수·소수·bool·지나치게 큰 수량 통과 / COMMIT 실패 후 연결이 막힘 |
| 검증 중 발견·수정 | 발주 등록 더블클릭 시 발주 2건 생성 / Windows에서 같은 포트에 서버 2개가 떠 요청이 나뉨 / 더블클릭 시 화면 다시 그리기가 겹쳐 표가 잠시 사라짐 |
| 부족 품목 요약 검증 | 권장 발주량 계산 테스트(7일 밖 제외, 입고 예정 반영, 정정 반영), 가짜 클라이언트로 Claude 응답·지어낸 숫자 거부·거절·API 오류·패키지 없음 테스트, 브라우저에서 권장량 "발주" 더블클릭 → 발주 1건·부족 해제 확인. **실제 Claude API 호출은 아직 검증 안 함**(이 환경에 패키지·인증 정보 없음) |
| 가정 | 단위(개/kg), 발주 기준 수량, 부분 입고 후 잔량 처리 방식, 권장 발주량 공식 → 가상 인터뷰([virtual-interview.md](virtual-interview.md)) 기준. 실제 운영자 인터뷰로 확인 필요 ([질문·시나리오](cafe-inventory-discovery.md)) |
| 미구현 | 로그인/작업자 구분(actor 필드만 존재), 품목 추가 화면, 다중 매장 |
