# 카페 발주·입고·재고 관리 (v0.3 — 매장 여러 곳, 품목 추가, 작업자 기록)

```bash
python server.py            # http://localhost:8000 (cafe.db 자동 생성, 샘플 품목 5개)
python -m unittest -v       # 서버·로직 테스트 75개(업무 사례 포함, OpenAI API는 호출하지 않음)
node --test test_client.mjs # 화면 요청 처리 테스트 8개(client.js)
```

포트·DB 경로는 환경변수 `PORT`, `CAFE_DB`로 바꿀 수 있다. 같은 포트에 서버를 두 번 띄우면 두 번째는 바로 실패한다.

## 업무 사례 (scenarios.json → test_scenarios.py가 그대로 재생)
1. **정상 입고**: 원두가 기준(2kg) 이하 → 5kg 발주 → 5kg 도착 → 입고 완료
2. **부분 입고**: 우유 10개 주문 → 8개 도착(입고 버튼 더블클릭 포함) → 잔량 초과 입고 거부 → 거래처 결품으로 잔량 취소
3. **수량 정정**: 컵 80개 도착인데 100으로 입력 → 마감 전 장부 110 vs 실제 90 → 이력에서 원인 확인 → 입고 기록 100→80 정정 → 실사 차이 0

새 예외 사례는 scenarios.json에 단계만 추가하면 반복 검증된다.

기본 기능은 의존성 없음(Python 3.13 표준 라이브러리 + SQLite).

## 부족 품목 요약 (AI는 숫자를 만들지 않는다)
- **계산**(`inventory.shortage_report`): 최근 7일 사용·폐기량(정정 반영) → 하루 평균, 남은 일수, 입고 예정 수량, 권장 발주량 = 7일분 + 발주 기준 − (현재고 + 입고 예정). 재고 목록 화면에 바로 표시되고 "발주" 버튼으로 권장량을 발주한다.
- **문장화**(`summary.py`): 기본은 규칙 기반 문장. "AI로 다시 쓰기"를 누르면 ChatGPT(OpenAI API, 기본 모델 `gpt-4o-mini`, 환경변수 `OPENAI_MODEL`로 변경)가 부족 품목의 **급한 순서**와 품목마다 **정해진 안내 문구 3개 중 하나**(오늘 주문 / 이번 주 안에 / 입고 예정분 먼저 확인)만 고른다. 응답은 JSON 스키마(Structured Outputs, strict)로 받는다.
- **문장은 서버가 조립한다**: 모델은 자유 문장을 쓰지 않으므로 수량·단위·기간을 지어내거나, 품목 이름 속 지시문에 따라 문장을 바꿀 수 없다. 부족 품목을 빠짐없이 한 번씩 고르지 않았거나 정해진 문구가 아니면 버리고 규칙 기반 문장을 쓴다. 패키지·인증 정보가 없거나 API 오류·거절·잘린 응답이 나도 같은 문장으로 대체하고 이유를 화면에 표시한다.
- **AI의 역할이 작다**: 지금 AI가 하는 일(급한 순서·문구 선택)은 남은 일수로 정렬하는 규칙으로도 대부분 대신할 수 있다. 실제 운영자가 어떤 요약을 원하는지 듣고 AI를 유지할지 정한다.
- AI를 쓰려면 `pip install -r requirements.txt` 후 `OPENAI_API_KEY`를 설정한다.
- 가정한 업무(일주일분 발주 등)는 [virtual-interview.md](virtual-interview.md)에 있다.

## 설계 요점
- **재고 = 변동 이력(stock_movements)의 합계.** 수량 컬럼을 직접 고치지 않으므로 이력과 재고가 어긋날 수 없다.
- **중복 방지**: 모든 쓰기 요청에 `idempotency_key`(UNIQUE). 입고 버튼을 두 번 눌러도 첫 결과를 돌려준다.
- **동시성**: 쓰기는 `BEGIN IMMEDIATE`로 직렬화. 스레드 8개가 동시에 사용량을 기록해도 합계가 맞다(테스트).
- **정정**: 삭제 없이 차이만큼의 `correction` 기록을 추가(0 = 취소). 사유 필수.
- **부분 입고**: 발주 상태(발주됨/부분 입고/입고 완료/종결)는 입고 합계에서 계산. 잔량 초과 입고 거부, 잔량 취소 가능.
- **마감**: 실사 수량과 장부 차이를 `adjustment` 기록으로 남긴다.

재고 목록(+품목 추가·사용·폐기·마감) / 발주·입고 / 품목별 변동 이력(+정정)

## 매장·품목·작업자
- **매장**: 화면 위의 매장 선택·"매장 추가". 재고 목록·발주·부족 요약은 선택한 매장만 보여 주고(`?store=번호`), 같은 품목 이름을 매장마다 쓸 수 있다. 이전 버전 DB는 처음 열 때 자동으로 "본점"으로 옮겨지며(테스트: test_stores.py) 기존 기록은 그대로다.
- **품목 추가·수정**: 추가는 이름·단위·발주 기준·기초 재고(더블클릭해도 한 번만). 수정은 이름·발주 기준만 — 단위는 기존 이력의 뜻이 바뀌어 고치지 않는다.
- **작업자**: 화면 위에 이름을 입력해야 기록할 수 있고, 입고·사용·폐기·마감·정정·발주 등록·잔량 취소에 이름이 남는다(이력 화면에 표시). **로그인·비밀번호는 없다** — 이름을 믿는 방식이라 누가 했는지 구분용이지 보안 장치가 아니다.
